# Experimental IMX335 binning

Withdrawn after the user reported a noise-filled RT60 image on 2026-10-18.
Register mocks do not establish physical output or ISP compatibility. This
experimental driver is excluded from RT30 R2, which uses the original SDK driver.

Starts from the unmodified SDK full-resolution setup and adds local mode ID 7.
2x2 register/timing facts follow the ST-contributed
[Zephyr driver](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/video/imx335.c).
VMAX=4500, HMAX=275 target 60 FPS; binning line time is half the original
30 FPS line time. Exposure conversion uses that duration and minimum SHR0=17.
Initialization errors propagate and cannot mark the object initialized.

The board normally requests vertical flip before initialization. Binning has
different inverted-readout phase registers, so those are applied after the
binning table. Their register facts follow the
[Linux IMX335 driver](https://github.com/torvalds/linux/blob/master/drivers/media/i2c/imx335.c).
Inference: AREA3 inverted start is this mode's normal 0x00a8 plus its 0x0f60
height, or 0x1008, adapting Linux's 0x00b0 + 0x0f60 = 0x1010. Horizontal
reverse retains the SDK setting. Post-init mirror/flip updates apply the proper
binning phase table, with the fixed 60 FPS timing. This is a single-sensor driver.

Host fake-I2C tests execute the real driver for both modes, original clock setup,
exposure limits, flip-before-init, post-init flip changes and write errors.
They do not validate sensor output, physical timing, color or image orientation.
